# 麦橘思域 · Noosphere

> 一个人，在具体的关切下，挑出来觉得值得记下来的东西。

700+ 跨领域概念的结构化笔记，覆盖哲学、心理学、经济学、社会学、传播学等学科。持续增加中。

每个概念有固定格式：**核心机制 + 入口场景**，加上现实锚点和适用边界。概念之间通过 `[[wikilink]]` 相互引用，形成有机生长的知识网络。

## 怎么用这个仓库（按需选择）

### 方式一：直接在网页上读（零门槛）

打开 [概念页索引](概念页/INDEX.md)，所有概念按学科排列，点击即可阅读。

适合：随便翻翻、找某个概念、了解这个库大概有什么。

### 方式二：下载到本地，用任何编辑器读

1. 打开仓库主页，点绿色的 **Code → Download ZIP**
2. 解压后得到 `noosphere-main` 文件夹
3. 进入 `概念页/` 目录，用你习惯的编辑器（VS Code、Typora、甚至记事本）打开任意 `.md` 文件

`.md` 文件是纯文本，任何设备都能打开。不需要安装任何东西。

### 方式三：用 Obsidian 打开（推荐，获得图谱视图）

[Obsidian](https://obsidian.md/) 是一款免费笔记软件，支持双向链接和知识图谱可视化。

1. 先把仓库下载到本地（方式二的步骤 1-2）
2. 打开 Obsidian → **打开文件夹作为 Vault** → 选择解压出来的 `概念页/` 文件夹
3. 左侧文件列表浏览，或点左下角 **图谱视图** 看概念之间的关联关系

概念页里的 `[[概念名]]` 会自动变成可点击的链接，跳转到对应概念页。

### 方式四：Git 克隆 + Obsidian Git 插件（自动同步更新）

如果你熟悉 Git，这是保持与仓库同步的最省心方式：

```bash
git clone https://github.com/MERJIC/noosphere.git
```

然后在 Obsidian 里：
1. 以克隆下来的 `概念页/` 为 Vault 打开
2. 安装 **Obsidian Git** 插件（设置 → 第三方插件 → 搜索 "Obsidian Git"）
3. 设置自动拉取间隔（比如每天一次）

之后仓库有新概念，你的本地会自动同步。不用手动下载。

## 这个库能做什么

**借结构。** 大多数知识积累是线性的——读到什么记什么，时间长了变成碎片。这套模板逼着你回答三个问题：属于哪个学科、是什么结构模式、能用在哪里。把概念想清楚，而不只是摘录。

**借库存。** 700+ 个概念经过筛选沉淀，可以直接 fork，在这个基础上往自己的方向延伸。

**跨领域连接。** 概念之间通过 `[[wikilink]]` 双向引用自然形成关联网络。同一个机制在不同学科有不同名字——经济学的「柠檬市场」和传播学的「信息不对称」说的是同一件事。读着读着会发现，原来这些概念是通的。

**按实际问题反查。** `apply/` 标签对应现实场景。面对组织决策失效，检索 `apply/组织`；理解关系里的沉默，检索 `apply/关系`。概念不是用来收藏的。

**辨析近似概念。** 每个页面的「适用边界」专门处理容易混淆的概念对：沉默的螺旋 vs 多元无知 vs 偏好伪装，团体迷思 vs 阿比林悖论，道德风险 vs 逆向选择。搞清楚两个相似概念的边界，比理解每个概念本身更有用。

**给 AI 用。** 结构化的概念库是很好的上下文材料——让 AI 在写作、分析时引用有出处的概念框架，而不是泛泛生成。

## 概念长什么样

每个概念页的结构固定：

```yaml
---
name: 古德哈特定律（Goodhart's Law）
domain: [管理学, 经济学]
date: 2026-05-13
source: 对话整理
tags: [apply/组织]
---
```

正文必有两节：

- **核心机制** — 概念的原理、来源和本质
- **入口场景** — 一个具体场景，让抽象的东西有落脚点

常见可选节：

- **现实锚点** — 概念在不同语境下的多个案例
- **适用边界** — 概念的适用限制、与近似概念的辨析

### 示例：古德哈特定律

`domain: 管理学, 经济学` · `apply: 组织`

**核心机制**

「当一个指标变成目标，它就不再是好指标。」

一旦某个指标与奖惩挂钩，人们就会直接优化指标本身，而不是指标背后试图测量的真实目标——两者开始分叉。

**入口场景**

客服团队考核「工单关闭数量」，客服开始快速关闭工单；遇到复杂问题就拆成多张。管理层看到数量上升以为效率提高，实际上客户满意度在悄悄下滑。

**现实锚点**

- 教育：标准化考试分数作为质量代理指标 → 学校开始应试教学，分数上去了，实际能力没跟上
- 软件：用代码行数衡量工程师产出 → 提交变碎、代码变冗余
- 销售：只考核成交量不考核留存 → 拼命成交低质客户，流失率飙升

越容易量化的事，越容易被优化成空壳。应对方向不是「找到更好的指标」——新指标很快也会被 Goodhart——而是多指标组合 + 定性校验。

## 工具链：Concept Studio Spread

Noosphere 只负责**存概念**。建概念、管概念、让概念之间产生联系——这些工作由 **Concept Studio Spread** 完成。

👉 **[concept-studio-spread](https://github.com/MERJIC/concept-studio-spread)** — 独立仓库，免费开源

### 它能做什么

| 功能 | 一句话 |
|------|--------|
| **寓言故事** | AI 选一个冷门学术原理写成寓言，听完可存入概念库 |
| **摄入概念** | 丢一个 URL 或一段文字，AI 自动提取值得沉淀的概念并建页 |
| **概念跳跃** | 从已有概念出发，每次推荐 3 个新方向，链式探索 |
| **圆桌讨论** | 就任意议题发起多视角结构化辩论 |
| **关联分析** | 扫描全库链接关系，识别孤立节点和概念集群 |
| **知识卡片** | 将概念页转为图文卡片 |

### 你可能需要它的场景

**场景 A：你想在这个概念库的基础上建自己的库**

1. Fork 本仓库（noosphere）拿到 700+ 个现成概念
2. 安装 Concept Studio Spread 到你的项目里
3. 开始用「摄入」「跳跃」「寓言」往里加自己的概念

**场景 B：你想从零开始建自己的概念库**

1. 安装 Concept Studio Spread（不需要 fork noosphere）
2. 创建空的概念库目录
3. 用工具链从零开始积累

**场景 C：你只是想读概念，不想建库**

那你不装任何东西。直接在本仓库的 [INDEX.md](概念页/INDEX.md) 里翻就行。
